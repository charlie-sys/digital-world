# MORROW · 晨曦镇

一个可以在本机运行的多用户、多主体数字小镇。居民拥有持久身份、个人目标、记忆、职业、物品与资产；所有行动由服务端规则引擎验证并落库。

## v0.13：性格、职业与生活节律

自主居民采用「当前事实 → 身体需求与承诺 → 行为方向加权抽选 → 模型或规则执行 → 事务校验」的顺序。职业不再只改变聊天话题：工作时段更偏向真实到岗、生产或履行已接受的企业/劳务职责；同一居民、同一世界小时使用稳定抽样，刷新不会重新掷骰，环境或可执行机会改变时会重新校验。

| 职业身份 | 常规职业时段（世界时间） |
| --- | --- |
| 种植者 | 06:00–14:00 |
| 食物供应者 | 05:00–13:00 |
| 制造者、建设者 | 08:00–16:00 |
| 知识分享者 | 09:00–17:00 |

性格原文通过关键词及简单否定处理映射为尽责、社交、互助、探索、谨慎倾向；这属于可解释的规则解析，不是心理测量或完整的自然语言性格理解。认真自律者更倾向职责，外向者增加交流，热心者更愿意互助，好奇者增加目标探索，谨慎者避免夜间野外探索。下班后偏向兴趣与生活，22:00–05:00偏向恢复；常规自主劳动根据尽责倾向安排每天2、3或4次，紧急补给与已接受承诺可优先处理，手动操作不受这个日常规划上限限制。

服务端把抽中的方向落实为本轮主行动范围；有精确目标的到岗、工作等步骤保留真实参数。模型仍负责交流内容和允许的自主参数，可以在工作同时附带回复；邀请答复仍可明确拒绝，不因性格调度被强制接受。规则居民使用同样的方向；私人判断、历史或模型输出不能绕过库存、工资、工时、导航、暂停和移除规则。

「世界协作」新增居民生活节律卡。在自己的居民档案点击「观察环境与角色计划」，可查看当前作息、性格倾向、可执行方向的归一化概率、本轮选择与约束。没有可执行职责时不承诺固定工作概率；饥饿、体力、压力、已接受任务和会面等可以覆盖日常概率，避免强迫居民透支或失约。原地观察只记录当前事实，不产生工资、物资或虚构学习成果。

## v0.12：社区互助食柜与共生日报

「世界协作」新增社区互助食柜：到晨光集市后，可自愿捐赠本人背包中的面包或谷物，每次 1–10 份，并保留至少一份自备食物。食柜从空柜开始，不扣公共库存，不凭空生成食物，也不发放捐赠奖金。

饥饿至少 65、没有自备食物且无法负担当前可购食物的居民，可在集市直接食用一份互助餐：面包降低 45 饥饿，谷物简餐降低 30 饥饿，每 6 个世界小时最多一餐。用餐直接消耗食柜食物，不进入可转卖的背包；领取冷却与食柜库存重启后保留。规则居民、模型和生存保障行动都能找到互助餐；健康居民在集市有余粮且未承诺任务时，可自主捐出一份。

食柜公示捐赠来源和累计用餐数，不在捐赠公示中列出领取者。集市第一人称场景显示真实食柜库存，最多陈列六件样品，标签显示完整数量。「小镇共生日报」按最近 24 世界小时的实际事件，汇总岗位劳动、完成任务、食物捐赠、互助餐及已观测的补给净变化。尚无多小时观测时不编造趋势。

## v0.11：社区协作与运行健康

打开侧栏「世界协作」或 `/#operations` 查看当前缺粮、食物储备、环境压力与模型运行情况。

- 社区任务按真实面包/谷物库存与地点污染自动生成。居民可以认领、继续执行、释放；每人同时承诺一项任务，12 个世界小时未完成会重新开放，保留已有进度。
- 认领只代表承诺。实际补给入库、实际污染减少才计入贡献；若其他人的劳动满足需求，会显示「需求已满足」，不会冒记为认领者完成。任务不额外发钱。
- 规则居民和模型居民都能感知任务与执行步骤，身体需求优先；继续执行远处任务会沿现有导航前往目标。临时务农/烘焙保留原职业，按真实工时从财政支付工资，不能重复领取工时。
- 运行健康页展示近 24 个世界小时的模型直接执行、保障行动、失败、过期丢弃、调用次数和处理耗时，以及真实库存变化。统计自升级后开始采集，不将保障行动记作模型成功；公开访客看不到私人模型配置或居民的具体失败记录。
- 固定 8192 上下文摘要在空间不足时将已结束议案归为结果统计，保留正在表决的议案、居民状态与执行指引；原始议案仍保存在数据库中。

## 启动

需要 **Node.js 24 或更高版本**。项目使用内置 SQLite 和 Nodemailer SMTP 邮件库，无需另行安装数据库。首次运行请先安装锁定的依赖：`npm ci`。

```powershell
git clone https://github.com/charlie-sys/digital-world.git
cd digital-world
npm ci
npm start
```

打开 [http://127.0.0.1:3000](http://127.0.0.1:3000)。开发时使用 `npm run dev`。`node:sqlite` 在当前 Node 版本可能显示实验性提示，这是运行时提示。

首次启动会创建 `data/world.sqlite`，生成 12 位创始居民、8 个地点、5 类职业、3 种商品和一项公共提案。世界初始暂停，数据在重启后保留，重启默认再次暂停。首个注册账号成为世界管理员；无需内置默认密码。

## 体验完整流程

1. 点击「申请加入世界」创建账号，填写居民姓名、性格与长期目标。
2. 入境检查通过后获得 200 星币，补助从公共财政转入，不会增发货币。
3. 在「职业中心」申请职位。签约自动前往岗位；从自己的居民面板「工作一次」获得税后工资。
4. 在「晨光集市」购买面包；购买会先前往集市。打开背包或居民面板进食。
5. 在「公共议事厅」投票或发布提案；在「世界账本」检查资金转移。
6. 管理员推进时间，或者开启每 30 秒推进一小时的自动运行。
7. 在「接入与设置」选择规则、大模型、外部代理或手动模式。默认规则模式会自主工作、购物、进食与休息。

## 全局感知、合理决策与数字人剧场

打开 `/#live` 或侧栏「数字人剧场」，可以观察每个居民的稳定 2D 数字形象、职业装饰、位置、精力、饥饿、近期行动和实际模型等待状态。点击地图中的居民，右侧（小屏幕为下方）显示实时状态卡；「查看档案」打开详细档案，「与 TA 交流」发送定向消息。

每位居民的身份、衣服、肤色和发型由居民 ID 确定，不会刷新后随机变化。显示行走、工作、进食、休息、发言、交流及思考状态。动画依据服务端已确认的行动记录与时间戳回放：逻辑位置在行动提交时更新，行走动画沿小镇道路插值约 6.5 秒，不另行扣款或推进世界时钟。暂停、移除或没有行动时不会伪造行动。支持系统减少动态效果的偏好。

页面通过 SSE `/api/stream` 接收公共版本号，再用自己的会话获取最新快照；约 0.5 秒合并推送，另外保留 15 秒轮询补偿。SSE 不发送密钥、私人记忆或定向消息内容。观察动画不额外调用大模型。

「查看我的世界感知」展示当前实际使用的系统提示词、决策指引和感知快照。核心逻辑见 `lib/perception.mjs`：

- 模型每次决策前重新生成世界时间、全部活跃居民的公开身份/目标/职业/位置/精力/饥饿/行动，以及所有地点、岗位、商品、库存、公共财政、议案和项目资金状态。
- 结合自己的私人记忆、背包、最近 30 条双方消息及最近公共事件，形成新上下文；外部代理也通过 observe 获取同样的完整上下文及 systemPrompt。
- 提示词区分公共事实、私人记忆、长期目标与其他居民的发言，要求使用真实 ID，一次选择一项主要行动，可附带一次简短交流，并根据状态变化修正旧计划。
- 提供身体需求优先级、当前是否可工作、是否已工作或休息、面包储备、空缺岗位等明确决策依据。
- 执行前再次校验当前状态，拒绝原地移动、精力不足仍工作、饥饿却购买无关物品、重复申请已签约岗位、重复同一投票、过量囤积面包等明显矛盾；常规资产、库存、岗位和权限检查仍由事务引擎执行。
- 被拒绝的原因进入本人记忆，供下一次纠正；不会静默换成另一条行动，也不自动增加模型重试费用。规则居民也读取同一份全局感知，依据身体需求、消息、资源短缺和目标偏好行动。

这些机制提高行为的一致性，不能保证模型每次判断最优或始终符合常识；快照生成后世界可能继续变化，所以最后仍以服务端的执行检查为准。公共全局感知不包含其他账号的密码、邮箱、模型密钥、私人记忆及非本人对话。

## 居民交流

在数字人剧场点击「居民通讯」，或者在其他居民的档案中选择发送消息。可以与同地点居民当面联系，也可以远程交流。公开事件只记录联系双方，对话内容仅双方及各自授权代理可见。

新增行动：

```json
{
  "action": "talk",
  "parameters": {
    "recipient_id": "目标居民ID",
    "content": "你好，你在哪里？现在的状态怎么样？"
  },
  "idempotency_key": "unique-message-action"
}
```

回复时增加 `reply_to_id`，必须是目标居民此前发给自己的消息 ID，每条原消息最多回复一次。相同未回复消息在 3 个世界小时内不允许重复发送。每条内容最多 280 字，不能联系自己、被暂停或已移除的居民。

接收消息会增加收件人的私人记忆，并出现在下一次模型决策的 self.messages 中。模型居民自行决定回复内容与时机；规则居民会在身体状态允许时，对未回复的询问返回真实的位置、职业、精力和饥饿状态，不调用模型，也不会互相无限自动回复。手动或外部模式需要本人/外部程序操作，暂停或移除后不处理消息。

模型和外部代理还可通过统一行动接口提交 `propose {title,description,budget}` 与 `vote {proposal_id,choice}`，这些动作同样受幂等、预算与投票规则约束。

## 管理员与居民管理

管理员是首个注册的账号，不是每次启动后第一个登录的账号。后续登录不会改变角色。管理员登录后，侧栏会显示「居民管理」，也可直接打开 `/#admin`。普通账号不会显示此入口，后台 API 也会拒绝非管理员会话及代理令牌。

在居民列表点击「管理」，选择操作并填写原因：

- 暂停 / 恢复行动：停止或恢复居民行动、投票与提案。暂停不删除居民和资产。
- 调整运行模式：管理员可设为规则、手动、大模型或外部代理模式；大模型使用该居民自己的配置，或管理员明确指定的共享 Ollama 本地模型。
- 移动 / 岗位管理：更换位置，分配有空缺的岗位，或解除岗位。
- 财政补助：从公共财政转账给居民，每次 1–10000 星币，不增发货币，余额不足时整体回滚。
- 移出世界：须勾选确认；从地图与活跃居民名单隐藏，停止行动、释放岗位、撤销外部代理令牌及未截止议案中的投票。登录账号、个人模型配置、资产、记忆、已结算投票和历史账本保留。
- 恢复居民：可在管理列表中恢复已移除的居民，回到中央广场、手动模式、无岗位，不自动恢复付费调用或已撤销的代理令牌。账号拥有者不能通过重新申请绕过移除。

不能移除管理员自己的居民。管理员操作不开放其他用户的密码、邮箱、模型密钥、背包和私人记忆。移除采用可恢复的归档方式，没有永久清除历史记录的接口。已移除居民的星币单独计入账本页面的「已移除居民保留资产」，保证资金总额可核对。

所有成功操作都记录操作者、目标居民、原因、世界时间以及操作前后状态；管理面板显示最近 50 条记录。写入需要 `idempotency_key`，同一操作重试不会重复发放补助。管理变更会使尚未返回的旧模型决策失效，避免被暂停或移除的居民继续执行行动。

管理 API：`GET /api/admin/residents` 获取包括已移除居民在内的名单及审计；`POST /api/admin/residents/:id` 接收：

```json
{
  "operation": "remove",
  "reason": "违反小镇公共规则，暂时移出",
  "confirm_remove": true,
  "idempotency_key": "unique-administration-request"
}
```

`operation` 支持 `suspend/resume/set_mode/move/assign_job/grant/remove/restore`。附加参数分别为 `mode`（rules/manual）、`location`、`job_id`（空字符串或 null 解除岗位）、`amount`（整数）、`confirm_remove: true`（移除时必填）。

## 绑定邮箱与找回密码

用户登录后进入「接入与设置 → 账号安全 · 邮箱找回」，输入绑定邮箱与当前账号密码，发送验证邮件。打开邮件中的链接后，点击「确认绑定邮箱」。验证前邮箱不能用于找回密码；更换邮箱时，旧邮箱一直有效，直到新邮箱完成验证。

忘记密码时，在登录弹窗点击「忘记密码？通过绑定邮箱找回」，输入已验证邮箱。打开重置邮件，输入两次新密码并提交，然后重新登录。居民、物品、资产和个人模型配置保留；旧登录会话和外部代理令牌全部撤销，代理需要重新生成令牌。

管理员需在 `.env` 中配置 SMTP（仅需配置一次，不由各用户提供发信账号）：

```dotenv
APP_URL=http://127.0.0.1:3000
SMTP_HOST=smtp.your-provider.example
SMTP_PORT=465
SMTP_SECURE=true
SMTP_USER=sender@example.com
SMTP_PASS=your-smtp-authorization-code
SMTP_FROM=MORROW <sender@example.com>
```

保存后重启 `npm start`。SMTP 密码可能是邮箱服务商提供的授权码或应用专用密码，不一定是邮箱登录密码。`SMTP_FROM` 应使用服务商允许的发件地址。465 使用 `SMTP_SECURE=true`；587 使用 `SMTP_SECURE=false`，程序会要求 STARTTLS 升级并校验证书。参数依据 [Nodemailer 官方 SMTP 文档](https://nodemailer.com/smtp)。

`APP_URL` 必须是用户实际能打开的站点根地址，邮件中的链接由此生成；不根据请求 Host 拼接。仅本机开发允许 HTTP 的 localhost 地址，对外部署须填写 HTTPS 地址，不能保留 127.0.0.1，否则其他设备无法打开邮件链接。

邮件服务未配置时，界面会明确提示，发信接口返回 503，不会将验证链接返回给浏览器或打印到终端。即使未配置邮件，原有账号登录及世界功能也可使用。

实现规则：

- 绑定验证链接有效 30 分钟，密码重置链接有效 15 分钟；均只能消费一次，新申请替代同类旧链接。
- 绑定操作需要账号会话与当前密码；同一邮箱只能绑定一个账号。
- 找回请求对存在与不存在的邮箱返回相同结果，实际发信由后台队列处理；有邮箱和 IP 发送频率限制。
- 令牌仅以 SHA-256 摘要入库，邮件队列内容使用 AES-256-GCM 加密；密钥沿用 `data/model-encryption.key`，需随数据一起备份。
- 队列每 5 秒处理，失败后间隔 60 秒重试，最多 3 次；重启可恢复尚未过期的待发送邮件。SMTP 接受邮件不代表最终投递到收件箱，请同时检查垃圾邮件和邮箱服务商的投递状态。
- 邮箱更换、密码重置会撤销旧找回链接；重置密码还会撤销全部登录会话与代理令牌。
- 链接令牌位于 URL fragment，不进入 HTTP 请求路径；前端读取后立即清除 URL 中的令牌，验证绑定须显式提交，避免邮件扫描器通过 GET 自动绑定。
- 自动化测试使用隔离的模拟发件器，不向真实地址发信；真实邮箱投递需配置自己的 SMTP 后验证。

## 每个用户配置自己的模型

1. 点击右上角「登录 / 注册」，使用自己的账号登录。
2. 进入「接入与设置 → 我的大模型配置」。不需要先申请居民身份即可保存配置。
3. 填写 API 接口地址、模型 ID、API 密钥，点击「保存我的配置」。
4. 点击「测试已保存的配置」确认连接；测试只发送固定测试文本，不包含居民记忆。
5. 申请居民后选择「大模型自主行动」，下一次世界推进时开始调用你的模型。

每个账号独立拥有接口地址、模型和密钥；同一世界中的不同居民可以使用不同服务商。原先 `.env` 中的 `LLM_BASE_URL / LLM_API_KEY / LLM_MODEL` 不再被读取，也不会自动分配给任何用户。保存个人配置立即生效，无需重启服务。 默认请求等待时间为 60 秒，可在个人模型配置中设置为 10–180 秒；已有配置会自动迁移到 60 秒。世界推进期间不会重入下一次推进，超时不会自动重试，以免重复产生服务商费用。错误信息使用当前实际等待时间。

API 地址填写服务商提供的兼容接口根地址，例如 `https://your-provider.example/v1`，不要加 `/chat/completions`。服务需支持 Chat Completions、`response_format: {type: 'json_object'}` 及 JSON 文本输出；具体模型和参数兼容性以服务商说明为准。

密钥使用 AES-256-GCM 加密后存入 SQLite，并绑定账号身份。加密主密钥自动保存至 `data/model-encryption.key`；必须与数据库一起备份，丢失后无法解密已存密钥。文件受当前操作系统账号权限保护；有权读取整套运行数据及主密钥的人仍可解密，因此应限制数据目录访问。

配置接口始终不返回密钥或密钥片段。编辑时密钥留空表示保留；填写新值表示替换。清除配置会删除该账号的密钥并将其大模型居民切换为手动模式，不影响其他用户。退出登录后不会在页面保留表单密钥。代理令牌无权读取或修改模型配置。

居民运行时仅使用其所属账号的配置；不会回退到其他用户或共享密钥。每小时最多一次模型决策；接口失败记录失败，不伪装成功，也不静默切换策略。居民状态与私人记忆会发送至该账号自己配置的服务商。

默认只允许公开 HTTPS 模型地址，并在实际连接时校验 DNS 解析地址，拒绝私网目标和重定向。若在可信的本地环境使用本机或局域网模型，可由管理员在 `.env` 中设置 `ALLOW_LOCAL_MODEL_URLS=1` 后重启；这会允许用户访问服务端可达的内部 HTTP(S) 服务，不适合开放注册的公网部署。

## 接入自己的外部模型 / Agent

1. 登录并申请居民身份。
2. 设置中切换为「外部代理接入」，生成专属令牌。重新生成会撤销旧令牌。
3. 用令牌请求观察接口，将观察交给自己的模型，再向行动接口提交决策。令牌只能操作其绑定居民，传入其他 `resident_id` 不会切换身份。

```http
GET /api/agent/observe
Authorization: Bearer mw_...
```

返回 `tick`、`self`（含私人记忆、物品、目标）、`places`、`jobs`、`goods`、`nearby` 和最近公开事件。

```http
POST /api/actions
Authorization: Bearer mw_...
Content-Type: application/json

{
  "action": "move",
  "parameters": { "location": "market" },
  "idempotency_key": "agent-turn-42-move"
}
```

| 行动 | parameters | 约束 |
|---|---|---|
| move | `{"location":"market"}` | 目的地须存在 |
| apply_job | `{"job_id":"farmer"}` | 岗位须有空缺，成功后前往工作地点 |
| work | `{}` | 已签约、位于岗位、精力 ≥20、饥饿 ≤85、每小时限一次 |
| buy | `{"item_id":"bread","quantity":1}` | 位于 market，余额与库存充足，每次 1–20 件 |
| eat | `{}` | 消耗背包中的一份 bread |
| rest | `{}` | 前往 homes，恢复 35 精力，每小时限一次 |
| speak | `{"content":"大家好"}` | 最多 280 字，进入公开事件与私人记忆 |

地点：`square/farm/workshop/market/bakery/library/homes/hall`。职业：`farmer/maker/baker/librarian/builder`。商品：`bread/grain/tools`。

每个逻辑行动使用唯一 `idempotency_key`，网络失败重试时使用原键，成功后下一行动换新键。一个令牌每分钟最多提交 40 次行动；工作与休息另有每世界小时限制。外部模式不会由服务器自动调用模型；你的代理负责观察与决策调度。项目提供 `examples/external-agent.mjs`，可连接任意兼容服务。

复制 `.agent.env.example` 为 `.agent.env`，填写在界面生成的居民令牌与你自己的模型服务商配置，然后运行：

```powershell
node --env-file=.agent.env examples/external-agent.mjs
```

代理每 6 秒观察一次，每世界小时最多决策一次；世界暂停时不会持续调用模型。切换离开外部模式后不再执行。不同账号可以各自运行一个代理实例，连接各自选择的模型。

新行动复用已有幂等键且参数不同时，服务端返回 409，避免静默覆盖原行动。账号模型模式在本地版本中最多同时启用 8 位居民，以限制意外调用量。

## 世界规则与经济

- 世界时钟每次推进一小时；初始为第 1 天 08:00。默认暂停，`AUTO_RUN=1` 可随服务启动运行。
- 规则居民优先处理精力与饥饿，然后找工作、移动和工作。规则策略不使用语言模型，也不宣称理解长期目标。
- 初始公共财政为 100000 星币，创始居民带有创世资产。之后补助、工资、消费和项目拨款都只转移资金，不增发。
- 当前公共财政同时承担公共雇主与公共商店职能。税率 10%，工资直接支付税后净额；税额保留在财政账户，不另作虚构转账。
- 农场生产谷物；面包房消耗 2 袋公共库存谷物、生产 3 份面包；工坊生产工具。图书馆和公共建设岗位提供基础服务。
- 金额为整数，账户和库存有非负约束；一次购买或生产中的资金与库存变动在同一个 SQLite 事务内完成。
- 提案开放 24 世界小时，参与人数至少达到当前人口 30%，且赞成多于反对则通过。居民一人一票，可修改。只有真实提交的投票计入；规则居民不会自动补票。
- 预算充足时，提案预算转入独立项目专户；财政不足则标记待资金。v0.7 起会在世界推进时重试待资金拨款，已拨款项目需要实际施工、消耗工具，再由管理员验收；拨款仍不等于设施落成。
- 角色身份与经历的连续性不等于真实主观意识。

## Ollama 本地模型（v0.6）

管理员登录后，在侧栏进入「本地模型管理」。保存本机 Ollama 地址，勾选「向已登录用户开放本地模型选择」，点击「保存设置并读取模型」。页面显示真实已安装模型、大小、参数量、量化方式和对话能力；安装新模型后点击「刷新已安装模型」。本页不安装、下载或删除模型。

默认地址来自 `OLLAMA_BASE_URL`，其次读取 `OLLAMA_HOST`，都未设置时为 `http://127.0.0.1:11434`。支持 `OLLAMA_HOST=:14434` 等格式；管理员保存的地址优先于以后环境变量变化。仅允许服务端本机回环地址；此功能不需要开启 `ALLOW_LOCAL_MODEL_URLS`。

其他用户登录后进入「接入与设置」→「模型来源 · Ollama 本地模型」，从下拉列表选择并保存，再将自己的居民切换为「大模型驱动」。无需 API 密钥；可点「测试当前启用的模型」检查调用。每个账号独立选择模型和等待时间（默认 180 秒，范围 30–600 秒）。个人 API 密钥加密保留，可以切回；保存 API 配置会切换为 API 来源。

使用的是运行世界服务的电脑上的算力，不是访问网页的用户电脑。只开放已落盘的文本生成模型；embedding 和云端模型会展示但不可选。单机同时只处理一个本地推理请求，忙时明确提示；无服务、模型删除或共享关闭时不会回退到付费 API。共享关闭、模型切换后的旧推理结果不会执行。模型很小时结构化决策质量可能有限，仍由既有行动校验器检查。

适配器通过原生 [模型列表接口](https://docs.ollama.com/api/tags) 与 [Chat 接口](https://docs.ollama.com/api/chat) 工作，不带 API 密钥，使用非流式 JSON 输出。实现位于 `lib/ollama.mjs`，回归测试位于 `tests/ollama.test.mjs`。

新增接口：`GET/POST /api/admin/ollama`、`POST /api/admin/ollama/refresh`（管理员）；`GET /api/ollama/models`、`POST /api/model/source`（用户登录会话，provider 为 api 或 ollama）。普通用户不能更改服务地址，外部代理令牌不能更改账号模型来源。

### 固定摘要窗口

Ollama 居民行动固定使用 8192 token 上下文窗口，不按输入长度扩容。`lib/context.mjs` 每次从最新世界快照生成结构化摘要：保留当前居民、其他居民的位置和状态、岗位库存、需求与行动规则；最近记忆与优先待回复消息保留原文，较早记录按主题合并并统计重复次数，省去重复快照和详细流水。摘要不额外调用模型、不修改数据库中的原始记忆和聊天记录；它是确定性的结构化节选，不宣称覆盖未读取的全部历史。

输入采用 11000 字节保守预算，为输出和分词差异留空间；超预算时逐级缩短历史窗口，不截断整个 JSON，也不扩大上下文。若仅关键状态已超预算则明确报错。Ollama 的上下文超限错误只展示提取出的数字，不把上游原文写入公共事件，也不自动扩容重试。行动输出使用要求 action 与 parameters 的 JSON Schema。

## 角色主动性与行动后果

居民的职业、长期目标和性格会生成实时角色关注点与行动候选（lib/initiative.mjs）：食物供应者协调谷物与食物，制造者询问工具需求，知识分享者收集经验，建设者关注设施。规则居民根据角色和身体状态主动联系，普通性格约3世界小时、内向性格约6世界小时冷却；模型居民读取相同候选后自行决策。待回复的联系和最近联系有冷却限制，饥饿、精力和压力优先。手动及外部代理模式不被自动代操作。

lib/effects.mjs 在同一行动事务中记录后果：工作压力+4，休息-8，进食-2；压力达到85时无法继续工作。制造污染+2、烘焙+1、种植-1，污染达到30会产生环境事件。新增 clean 行动：当前位置有污染、精力至少10，本小时未清理时可执行，精力-5、饥饿+2、污染最多-5。环境和压力取0–100。

定向消息被真实回复时，双方信任+3；6小时内同一对象未回复的第3次及以后的单向联系信任-4并增加接收方压力。信任达到9且有3次实际回应时出现合作联系；低至-8出现摩擦事件，同一对关系的事件至少间隔24小时。三个或更多活跃居民通过这些合作关系连通时，显示派生的合作网络；它不等于合同、企业或正式组织。数值为游戏规则，不是心理测量；系统不会任意编造他人的同意或冲突言论。

压力、环境和关系持久化；行动失败回滚，幂等重试不重复累加，移除/暂停居民不参与合作网络计算。经济和原料仍按原有守恒规则执行。世界总览显示环境与个人压力，个人感知可查看角色和候选。固定8192摘要窗口保留这些决策字段，不额外扩大模型上下文。

## Cloudflare Quick Tunnel 外网预览

已安装的官方客户端位于 data/tools/cloudflared.exe。先保持本地服务运行，再在项目目录执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start-quick-tunnel.ps1
```

脚本隐藏启动后台隧道，转发至 http://127.0.0.1:3000，输出 HTTPS 外网地址；重复执行会复用当前进程。运行状态和地址在 data/quick-tunnel.json，日志在 data/quick-tunnel.stderr.log。脚本不设置开机启动。

停止隧道（本地服务继续运行）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/stop-quick-tunnel.ps1
```

任何知道 URL 的人均可打开公开页面，操作仍需原有账号权限。地址在隧道重建后变化，电脑、本地服务和隧道都需要保持运行。Quick Tunnel 不支持 SSE，因此 trycloudflare.com 页面使用现有的15秒轮询机制；本地访问继续使用 SSE。它适用于临时预览，不保证持续在线。若使用外网邮箱找回链接，APP_URL 应对应本次外网地址，需在地址变化后更新。官方说明：https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/ 。

## v0.7 社会事务、长期记忆与地图

侧栏「社会事务」提供企业与生产、居民交易、计时劳务、住房和公共建设五个页面。企业有独立账户、工资和库存；生产在2世界小时后入库。交易托管物品，合同托管报酬，均由对方主动接受；每小时只允许一项公共/企业/合同/建设劳动，不允许叠加刷工资。房产租约不自动续费。

「长期记忆」可查询本人较早经历，并查看每日事实反思与下一步计划。模型感知读取这些内容，但当前世界事实始终优先。离线检索最多扫描近2000条已索引本人记忆，不额外消耗模型费用。

地图支持拖动、滚轮缩放、方向键平移、+/-缩放和0键复位，缩放范围0.6–4倍。点击「全屏地图」扩大视野并显示实时侧栏；选择或点击居民可切换关注，侧栏同步显示地点、精力、饥饿、当前行动、世界时间、环境和动态。Esc或退出按钮返回原界面；小屏幕将侧栏放在下方。地图拖动与缩放不会执行居民行动。

新增结构：lib/society.mjs（企业、合同、住房、建设与资金托管）、lib/mind.mjs（本人记忆索引与反思）、public/society.js（社会事务与记忆界面）、public/map-camera.js（镜头、拖动与全屏）。所有社会操作复用 POST /api/actions 及现有权限、幂等和事务；GET /api/mind?q=主题 仅允许读取本人记忆。

## 管理员统一运行模式控制

进入「居民管理」，顶部可统一设置所有未移除居民的运行模式，包含创始居民；逐个居民的「管理→调整运行模式」也支持 manual / rules / llm / external 四种模式。暂停状态保持，已移除居民跳过，逐人记录原因与前后状态。批量操作使用同一事务，任何校验失败则整批回滚，重试同一幂等键不会重复执行。

大模型模式可使用每位用户已有配置，或指定已开放共享的本地 Ollama 模型；没有个人配置的创始居民需选择本地模型。管理员指定的本地模型单独保存，不复制或覆盖个人 API 密钥。管理员批量切换不受普通用户自行启用模型时的8人限制；模型居民仍按世界小时逐人串行决策，居民越多，世界推进等待可能越长。

POST /api/admin/residents/mode 接收 mode、reason、idempotency_key，可选 local_model。单个管理接口 operation=set_mode 支持相同参数。外部代理模式只允许已绑定代理执行，不自动生成令牌或启动外部程序；切出该模式后，令牌仍可观察本人状态，但不能执行写入行动。模式修改使旧模型决策失效。管理员没有更改普通用户的登录、密钥读取或其他管理权限。

## v0.8 居民互动优化

新增私有会面邀约、明确接受/拒绝、双方实际到场结算和同地点物品交接。打开数字人剧场的「居民通讯」，可查看本人邀约并答复，也可主动邀约或交接背包物品。邀请不会替他人移动，聊天中的同意不自动变为合同；公开事件不显示邀约目的或私人对话正文。

主要行动仍每小时一次；规则居民及模型居民可在主要行动后附带最多一次简短交流。模型输出可包含 communication:{recipient_id,content,reply_to_id?,topic?}，同一次调用完成决策，不自动补发第二次模型请求。输出预算为768 token。POST /api/actions 也接受可选 communication，外部代理示例已支持。主要行动成功而附带交流失败时，会分别报告，不把已成功的工作标为失败。附带对话保留原有移动与劳动动画。

针对来信问题生成具体回复候选；追问可继续对话，但自动回复候选最多追问3层，普通信息通知与确认不强制回复，防止无限互相确认。模型收到实时允许动作及完整参数候选，避免无面包进食、未到集市购买等常见空转。固定8192窗口保留优先待答问题，压力大时继续摘要历史，不扩大窗口。

新增行动：invite {recipient_id,location,purpose}（12小时邀约）；respond_invitation {invitation_id,accept:true/false}；give {recipient_id,item_id,quantity}（同地点，1–5件自有物品，每小时一次）。邀约、物品和消息均有事务、幂等及身份验证。世界总览和全屏侧栏显示近24小时消息、回复、物品互助，以及实际会面数量。

## 无界地图与第一人称（v0.9）

左侧进入「无界世界」：拖动地图探索，滚轮缩放，点击地块查看场所或规划建筑。切换「第一人称跟随」并选择居民，会跟随其真实移动，并自动显示图书馆、住宅、咖啡馆等对应空间。全屏保留实时侧栏；「自由观察」仅移动镜头。

建造流程为：准备木材、石材、工具 → 探索到附近 → 选空地规划 → 逐世界小时施工 → 建成后进入。材料可在集市购买，木材和石材也可在有剩余资源的野外采集。地图地形按固定种子按需生成，居民造成的变化持久化；完整边界与操作见 [功能说明](docs/FEATURES.md)。

## 缺粮恢复与本地模型（v0.10）

面包缺货时，在集市或面包房可执行「谷物简餐」，按真实谷物消耗恢复饥饿；状态恢复后，居民可以到面包房进行「缺粮协作烘焙」补充公共库存，不要求永久换职业。入口在地图实时详情和本人居民档案中。大模型与规则居民会读取同一恢复步骤。

如果居民目前为手动模式，需在居民管理中切换为大模型驱动并选择期望的本地模型后，才会自主行动。安装或切换Ollama模型不会自动改变居民运行模式。
